# pi-docker QoL features (branch: `features`)

## Context

pi-docker is a single-repo tool: `install-pi-docker.sh` (builds the image, installs the
`~/.local/bin/pi-docker` launcher and Pi packages, derives/saves service URLs from
`pi_configs/`) plus the `pi_configs/` deployer (`setup-pi-config.sh`). The launcher is a
managed file generated by the installer; no Docker image changes are needed for any
feature here. Work happens on the `features` branch; `main` stays at the published state
(`7b734ae`).

## In scope (this pass)

### F1 — Launcher CLI: `--help` + proper flag parsing + `--project DIR`
Rewrite the launcher's argument handling (currently only `$1` is inspected):

- `usage()` text inside the launcher: options, the `config`/`doctor` subcommands, env
  overrides. `-h|--help` prints it and exits 0.
- Parse leading known flags in any order; the first unknown arg (including unknown `--*`)
  ends parsing and everything from there passes through to Pi (preserves
  `pi-docker --model X` style usage).
- `--project DIR`: bind `DIR` (resolved via `cd -- DIR && pwd -P`, must exist) as
  `/workspace` instead of `$PWD`; clear error if missing.

### F2 — `pi-docker config` + single env store
- New store: `~/.config/pi-docker/env` (0600, `KEY=VALUE` lines, split on first `=`).
- Whitelisted keys: `SEARXNG_URL`, `LLAMA_BASE_URL`, `LLAMA_API_KEY`,
  `PI_DOCKER_MEMORY`, `PI_DOCKER_CPUS`, and the five provider keys
  (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GEMINI_API_KEY`,
  `GOOGLE_GENERATIVE_AI_API_KEY`, `GROQ_API_KEY`).
- Subcommands: `config set KEY VALUE` (URL keys validated; memory/cpus loosely
  validated), `config get KEY`, `config unset KEY`, `config list` (bare `config` = list;
  secret-looking values masked in list, shown only on explicit get).
- Runtime precedence (launcher + installer unchanged contract): shell env var > env
  file. Provider-key forwarding reads effective value (shell, then file).
- One-time silent migration in the launcher: legacy `searxng-url` / `llama-url` files
  are moved into the env file and removed (idempotent).
- Installer: `--searxng-url`/`--llama-url` and the `pi_configs/` derivation now write the
  env file instead of the legacy files (derivation logic itself unchanged).

### F3 — `pi-docker doctor`
A `doctor` subcommand that reports, one line per check, and exits 0/1:

1. Docker daemon reachable.
2. Image present + managed label (`io.pi-docker.installer`) — tells the user to run the
   installer if not.
3. Launcher version marker (parses the `# Managed by install-pi-docker.sh (vX)` line).
4. Packages present under `$DATA_DIR/agent/npm/node_modules` (both packages).
5. Data dirs present with sane modes.
6. Saved settings: which whitelisted keys are set (from env file), which are missing.
7. URL reachability for saved `SEARXNG_URL`/`LLAMA_BASE_URL` (curl `--max-time 3`,
   skipped with a note if curl is absent).
8. Tailscale DNS probe: bash `/dev/tcp` connect to `100.100.100.100:53` — reports
   reachable vs "not reachable; is tailscaled running? (use --no-tailnet)". This gives
   visibility without the blocking preflight (F-preflight is a later item).
9. Image sandbox deps (`bwrap`, `socat`, `rg`) via one fast `docker run --entrypoint sh`.
10. `~/.local/bin` on PATH.

Summary line: `N passed, M failed`. No prompts, no network installs, ~seconds total.

### F4 — Deployer `--check` and `--restore`
In `pi_configs/setup-pi-config.sh`:

- `--check`: run the existing status pass (NEW / UP-TO-DATE / OVERWRITE-with-diff), print
  the report, exit 0 if in sync / 1 if drift — no prompts, copies, backups, or package
  work. Ignored together with `--restore` (die if combined).
- `--restore`: for each destination in the selected target that has a `.bak`, show the
  list, prompt once (unless `--yes`), copy `.bak` back over the destination and remove
  the `.bak` (no `.bak` = nothing to restore).
- Bump deployer `VERSION=2.1.0`; document both flags in its usage + `pi_configs/README.md`.
